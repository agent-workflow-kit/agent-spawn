# Fake binaries: fidelity notes

The fakes in this directory stand in for `claude-session`, `termctl`, `wtctl` and `tmux` in agent-spawn's tests. They are a test aid, not a re-implementation: where a fake is simpler than the real program it says so here, and anything not checked against the real program is listed under "Unverified".

## How a fake behaves

- Standard-library Python only, run through the stubs in this directory (`claude-session`, `termctl`, `wtctl`, `tmux`). The fixture puts a `python3` symlink to the test interpreter first on `PATH` (the stubs start with `#!/usr/bin/env python3`), so the 3.12/3.13 test matrix runs the fakes under the version it tests; every `invoke` record in the log names the Python version. A fake refuses to run (exit 70) unless `FAKEBIN_LOG` is set to an absolute path in an existing directory, so it cannot be used by accident outside the `fakebin` fixture.
- A broken test setup (a corrupt or wrongly shaped state, counts or script file, an unknown `on_signal` name, a non-numeric or negative `sleep`, a non-integer `exit`, a scripted `error` with `exit: 0`) is one `fakebin: ...` line on stderr and exit 70, never a traceback. A scripted `error` without `exit` exits with the code the siblings give that error code (`usage` 2, `not_found` 10, `refused` 20, ...), else 1.
- A scripted `hang` never outlives its test: it ends with exit 124 after `FAKEBIN_HANG_SECONDS` (default 120) and when its parent process is gone (the harness passes its PID in `FAKEBIN_PARENT_PID`; without it the fake watches its parent PID, unless that is 1). A hung fake logs a `hang_ready` record once it is waiting, which tests poll for before signaling.
- Every call is logged to `FAKEBIN_LOG` (JSON lines): an `invoke` record before anything happens (argv, cwd, PID, a few environment variables) and an `exit` record (exit code, signals handled, stdin read). A call killed by an unhandled signal has no `exit` record.
- argv is parsed with the real tool's grammar: value flags take the next token even when it starts with `-` (getopt), `--flag=value` is equivalent, a boolean flag rejects `=value`, unknown flags are usage errors, and value grammars (labels, actors, decision ids, durations, ids, names) are the ones in the sibling interfaces. An argv the real tool refuses with exit 2 is refused with exit 2 and, with `--json`, the tool's error envelope.
- Canned outputs are built from the argv (and, for `claude-session`, `termctl` and `wtctl`, from a small state file next to the log), so the output of one call is consistent with the next. Every output is validated in tests against the schemas copied to `tests/sibling-schemas/<tool>/0.1.0-design/`.
- A scripted `gate` (a file path) holds a call until that file exists and then lets it answer normally; it logs a `gate_ready` record with the path once it is waiting (`fakebin.wait_for_gate(path)` polls for it), and like a hang it never outlives its test. `fakebin.clear_script(tool, command)` disables the rules added so far for a command (a disabled rule keeps its index, because answered calls are counted per rule index); rules that are already running (a hung `exec`) keep the behavior they started with. A rule scripted with `until_called="<subcommand>"` stops matching once the log holds a call of that subcommand of the same tool, so a scripted reply can depend on what happened (a `status` that reports a run live until `stop` was called) instead of on how many calls came before.
- A test scripts responses with `fakebin.script(tool, command, ...)`: `exit`, `stdout`, `merge` (into the canned output), `error` (the error envelope), `stderr`, `sleep`, `hang`, `on_signal`, `outcome`, `secret`, `child` (claude-session `exec` only: a real child process stands in for `claude`; it records the SIGTERM, SIGCONT and SIGHUP it gets in `<FAKEBIN_LOG>.child-signals`, `exec` passes a signal it handles to it and waits for it, and a `child_started` record names its PID). A scripted `error` is raised before the fake changes its state, as a refusing real tool changes nothing.
- Anything a fake does not implement exits 1 with `error.code: fake_unsupported`, a code that is in no sibling schema, so a test cannot mistake it for the real program.

## Verified against the real programs

`tests/live/test_fidelity.py` (marker `live`, never in CI) re-checks these against the real programs:

- the exit code and error code of every row of `tests/fakebin/fidelity_cases.py` marked verified (claude-session 0.38.4 and termctl 0.25.0 argument parsing; 89 rows on 2026-11-14), including `--` handling, value consumption, `--json=x`, human-only flags, the grammars, `verify-secret`, unknown session ids (exit 10, also for `label add`), the duration cap of 36500d, `list`/`forget` filter choices, and `--socket PATH` before a nested `label`;
- the `ACCEPTED` list: 15 argv the real programs pass at argument-parsing time and the fake accepts too (an empty `--env-allowlist-only`, an empty `--model`, `--max-turns +5` / a leading space / a non-ASCII digit / `1_0` (Python `int()`), both `--auto-exit` and `--no-auto-exit`, `--timeout 1.5h`, an empty `--setting-sources`, `--permission-profile=-x`, `--older-than 0`);
- the `DIVERGENCES` list: argv where the real program differs from the fake on purpose (see termctl below), pinned on both sides;
- tmux 3.5a: `-V` output, the "no server" errors (`error connecting to <sock> (No such file or directory)` for a missing socket, `no server running on <sock>` for a socket file nobody listens on and for a regular file), the unknown-option usage text, `-d`/`-D`/`-U` printing only the usage and `-q` being ignored, `kill-server`, an alias and an unknown command without a server, `start-server` succeeding silently, `;` as a command separator and `\;` as a literal, and the `new-window -P -F` output shape.

## Known simplifications

claude-session:

- Implemented: `start` (with `--resume`, `--fork`, `--dry-run`), `exec` (new and `--session-id` adoption), `resume`, `stop`, `wait`, `status`, `list`, `label add|remove`, `forget`, `reconcile`, `verify-secret`. `list` filters by label, state, kind, launch/run kind, mode, `--pending`, `--live`, `--needs-input`, `--tainted`, repo, report status and `--forked-from`, and applies `--limit`; the state shown is the fake's (`starting`, `working`, or the final outcome's). Not implemented (`fake_unsupported`): `report`, `transcript`, `export`, `kinds`, `cron`, `hook-event`.
- argv is parsed like Python's argparse, which the real tool uses: a separate-token value that looks like an option (`--permission-profile -x`) is a missing value (exit 2), `--flag=-x` is a value, global flags (`--json`, `--config`) must follow the command, `label` takes its action first, and `type=int` flags use Python's own `int()`. `--actor` and `--decision-id` have no grammar, only the caps of the interface (4 KiB, and 256 KiB in all, as escaped JSON; **unverified**: the real tool checks them after loading its config, which fails in the build environment). Durations are the real grammar (at most `36500d`; `--timeout` refuses zero, `--older-than` and `--grace` do not). The ids follow the real rules: fewer than 4 characters after `cs-` exit 2, anything else that is not a known, non-forgotten session (a 9-character or malformed id included) exits 10.
- There is no prompt positional or `--` prompt: the interface passes a prompt with `--prompt-file`, and the fake refuses a stray positional. If a caller was told "a prompt needs `--`", that applies to `claude` itself, not to `claude-session`.
- Sessions are known only if `start`, `exec` or `resume --fork` created them or a test seeded them (`fakebin.seed_session`); `label add` never creates one and `forget` drops it. Every id-taking command answers 10 for the rest, as the real tool does (verified for `status` and `label add`; the exit 10 of `stop`, `wait`, `forget`, `resume` and `exec --session-id` is from the interface). `stop` follows the run state: a pending run is canceled (`canceled`, outcome `not-started`), a final run is `already_final`, a live one ends `killed` (and a later signal to its hung `exec` is then recorded `stopped`); the state is the fake's own bookkeeping (**unverified**, from the interface). `resume` records each run (consecutive resumes count up) and `resume --fork` allocates a new session with `forked_from`; `status --run` and `wait --run` of a run the session never had exit 10 (interface, unverified).
- `exec` runs no `claude`: it finishes at once with the scripted outcome (`done` by default; a scripted `end_reason` replaces the outcome's end reason, e.g. `never_adopted` for `not-started`, an unverified combination), writes the outcome file (temporary file, rename, mode 0600; the real tool also walks parents with `O_NOFOLLOW`), and prints the outcome object. A scripted `hang` follows the interface's signal table (**unverified**, no real exec ran): SIGTERM and SIGHUP end the run `killed` (exit 15) with the outcome file written and end reason `forwarded_term`/`forwarded_hup` (`stopped` after a `stop`), SIGINT does the same with `forwarded_int` in a headless run and is ignored by an interactive one. Only the first signal counts: later ones (a different signal included) are dropped while the run is finalized. A failing `--outcome-file` write (missing parent, a directory, an empty path) never changes the outcome or the exit code: a warning on stderr, an `outcome_file_failed` record in the log, no temporary file left.
- Hooks, taint, third-party isolation, config files, launch-order validations (sandbox, cwd, paths), `--input-file` copies and the `expires_at` clock are not modeled. `--dry-run` plans are fixed shapes (an empty `origins`, `settings`, `hooks` and so on). Human output is not emulated (nothing is printed without `--json`, except `--version`).
- Interactive `exec`/`resume` need a TTY on stdin and stdout, as in the real tool; tests use a pty to cover that path.

termctl:

- Implemented: `open` (and `--dry-run`), `show`, `exists`, `list`, `rename`, `mark`, `unmark`, `focus`, `close`, `label add|remove`, `placements` (the built-in placement only, no config, from the interface: **unverified** against the real tool).
- With `FAKEBIN_TMUX=<tmux binary>` and `TERMCTL_SOCKET=<socket path>` (process tests only; the socket is a private server of the test) `open` starts its argv directly in a new tmux session (`new-session -d`, `exit-empty off`, global `remain-on-exit` from `--keep-on-exit`), reports the real pane PID, and `list`, `show`, `mark`, `close` and the other id-taking commands take the pane's state from tmux first (a pane tmux no longer lists is gone; a dead pane has `state: dead` and its `exit_status`); `close` runs `kill-pane`. The pane process gets the private server's environment, as with the real tool. No placement, session sharing, hooks or tag checks are modeled.
- Without `FAKEBIN_TMUX`: no tmux is involved. Panes live in a state file per socket path; a pane never dies by itself and every pane is `running`, `focus` always "switches" `/dev/pts/0` (it never answers `attach`: a test scripts that answer), and a marker's text is its name (the real text comes from config). Hooks, locking, the audit log, config, the tmux version check and the socket safety checks are not modeled; the "no server" state is "no pane was ever opened on this socket".
- `open --placement NAME` needs a defined placement, as the real tool does (exit 2, `usage`, nothing opened): `default` and the names in the environment variable `FAKEBIN_PLACEMENTS` (comma separated, set by a test with `extra_env`). **Pinned shape drift:** the fake's `default` placement prints `max_panes`, `layout` and `group_by` in `termctl placements`, while the real tool prints `session`, `target` and `origin`; agent-spawn reads only the plan it passes through, so neither is relied on.
- A scripted `open` response with `after_create: true` applies after the pane exists (a failure or a hang once termctl has created the pane), unlike a plain scripted error, which refuses before anything is created.
- `open` checks that argv[0] is an executable (using the `PATH` of `--env PATH=` when given), as the real command check does.
- The interface says argv without `--` exits 2; the real termctl 0.25.0 opened a shell pane instead (and a `--` with nothing after it exits 2). The fake follows the interface; the difference is pinned on both sides in `DIVERGENCES` (the real `open --dry-run` without `--` exits 0, the fake 2). This is an inconsistency in termctl (interface versus implementation), not something to rely on either way; it is reported to the user.
- Checked like the real tool (verified rows): an empty `--cwd`, an empty command (exit 12), `--override-escalation` without a terminal or a `human:` actor and with an `auto:` actor (exit 2, `open` and `close`), `mark` with an undefined marker (exit 2: the real markers come from config, the fake knows only the built-in `attention` with text `"\U0001f514 "` and any marker a test scripts with `fakebin.script("termctl", "mark", markers={"name": "text"})`), and the default session name `termctl`. A pane carries at most 32 labels (exit 2 after the id resolves; from the interface, **unverified**: the real tool answers a missing server first). An `argv[0]` containing `=` exits 2 (interface, unverified). Spellings of one socket path (symlinks, `//`, `..`) share state.
- A global value flag may precede a nested command (`--socket PATH label add ...`, verified).

wtctl:

- Implemented: `create` (worktree and throwaway, including the retry-after-crash `reused` result and per-repo unique names), `adopt`, `list`, `show`, `status`, `remove`, `forget` (with and without `--holder`), `label add|remove`, `locate`, `baseline check`, `reconcile`, `prune`. Not implemented (`fake_unsupported`): `bootstrap`, `extract`, `baseline accept`, `clone`, `export`, `cron`.
- No git is involved. `create` makes an empty directory under `<XDG_STATE_HOME>/wtctl-fake/worktrees/{host}/{path}/{name}` (the interface's `{root}/{host}/{path}/{name}`, `:` in the host replaced by `_`; throwaways under `throwaways/<id>`), so two repos with one worktree name do not share a directory; `remove` deletes only that directory. A branch must pass the rules of `git check-ref-format --branch` (no spaces, `..`, a leading `-`, `~^:?*[\`, `@{`, a trailing `/` or `.lock`, ...; the fake's own list, **unverified**: no git runs); a record holds at most 32 labels; `list --state` takes the record states of the interface; `create --dry-run` reports the id the next real create would take and consumes none. A global value flag may precede `label`/`baseline` (`--config X label add ...`). Dirty, unpushed, locked, in-use, integrity and baseline checks always pass unless a test sets `fake_dirty` or `fake_unpushed` on a record in the records file (then `status` reports `reason` `dirty` with `force_overrides: ["tracked"]`, or `unpushed` with `["unpushed_head"]`, and `remove` refuses 20 unless `--force`); `status` reports `human_required: true` for an adopted (not owned) worktree, but `remove` does not refuse it with 13 (**unverified**); scripting a refusal is the other way a test gets one. Bootstrap never runs (`state: none`); a test scripts `bootstrap_failed=<step>` on `create` to get exit 12 `bootstrap_failed` with the record kept `active` and `details.record`/`details.step`. An explicit `--name` is never suffixed (the fake follows wtctl's Create order, **unverified** against the real wtctl, issue 36): a collision with a live record of the repo exits 20 `branch_exists` (with `details.tip`) when the branch is template-built (no `--branch`, no `--detach`), never reused; an explicit `--branch` that is in use (`branch_in_use`) or a `--detach` name collision (`path_exists`, with `holder_id`) returns the record with `reused: true` when it is `active` and the `--holder` holds it, and is refused otherwise. `create --dry-run` applies the same refusals and never reuses (`dry_run` is false whenever `reused` is true). `bootstrap_failed` carries `details.record` as the whole record object and `details.step` as a bootstrap step object (the pinned `error.json`). `forget --holder` forgets an adopted record when it removes the last holder (an owned one never). `adopt` follows the interface (an already recorded path adds the holder, `existing: true`, for an `active` record only: `missing` exits 10, `unlinked`, `clone_missing` and `partial` exit 20 `unlinked`, `creating` exits 20 `path_exists` with `holder_id`; a path in the fake's throwaway root exits 2; a missing directory exits 10); the repo of a new adopted record is `--repo` or a fixed placeholder (the real one derives it from `origin`, **unverified**). `remove` without a TTY needs `--yes` (exit 13), `--force` and plain `forget` need a human actor, and holders other than `--holder` refuse with `held`.
- The real wtctl was a scaffold when this was written (every command exited 2 without an error envelope), so there is no live comparison; the fake follows `docs/interface.md` of wtctl and the pinned schemas only.

tmux:

- Only the client options, `-V`, `;` splitting, command aliases and the "no server" failure are modeled; every other command needs a scripted reply. A rule for a command also answers its alias (`ls` for `list-sessions`; the table is tmux 3.5a's), and a rule with an empty response is still a rule. `start-server` succeeds silently; `list-commands` is `fake_unsupported`. For real tmux behavior use the `private_tmux` fixture (a real server on `-S <tmp>/sock -f /dev/null` with a private `HOME`).

## Known fake leniencies (claude-session)

Places where the claude-session fake accepts or answers what the real tool (per its interface) would refuse or answer differently. Tests must not rely on them.

- `forget` of a pending or live session succeeds; the real tool refuses a live run.
- `start --dry-run` answers constants: `taints` is false and `would_refuse` is null whatever the session's state (use `fakebin.script` to get a refusal).
- `status` never reports a pending run unless a test scripts `pending_unadopted: true` (then a run nothing adopted yet, and not final, is reported `pending` in its launch phase with a null outcome; **unverified**, see Unverified), `recent_events` is always empty and `reconcile` finds nothing.
- The outcome-file refusal of launch step 2 (a path under a session-writable path) is not modeled.
- A plain `--resume` with `--cwd` is accepted; the real tool exits 2 when it differs from the stored cwd.

## Unverified

- claude-session: the real 0.38.4 in the build environment failed with an internal `ModuleNotFoundError` for every call that gets past argument parsing, so the human-only flag checks, `--actor` grammar, a missing `--prompt-file` and everything that needs state or config were compared with the interface document only (rows marked `False` in `fidelity_cases.py`). The shapes of `start`, `exec`, `status`, `stop`, `wait`, `list`, `forget` and `reconcile` outputs are the schema's, not observed.
- The sibling schemas are pinned to interface `0.1.0-design` and copied from the sibling commits recorded in each `PIN.json`; the real programs' released versions are far ahead of the fakes' `--version` (`0.1.0`).
- Signal behavior of the real `exec`, `termctl close` and `wtctl remove` is taken from their interface documents; none was exercised.
- Anything the fakes do not log or model (timing, concurrency between real sibling processes, lease contention) is not tested by them.
- The signal table of `exec` (end reasons, SIGINT ignored by an interactive run), the `stop` states, run bookkeeping across resumes and forks, and the `--actor`/`--decision-id` caps of claude-session are from its interface document only.
- The `/proc` dependence of the process tests is gone: the PID plus start-time identity of `private_tmux` comes from `ps -o lstart=` (the same on Linux and macOS). The one assertion that reads a process environment still needs `/proc` and is skipped elsewhere.
- Promotion (#29), not yet checked against the real programs (reported on the live-test issue #36): (A) the real `pane_pid` under tmux's default-shell wrapping and termctl's `pid: null` rules, against the host's self-identity requirement (`pane_proc` must equal the `supervise --host` process); (B) the real `claude-session status` of an unadopted promoted run (`pending: true`, phase `launch`, `expires_at`, the `expired`/`never_adopted` finalization), which the fake reports only when a test scripts `pending_unadopted`; (C) `claude-session start --resume <id> --mode interactive --json` with no prompt file; (D) `exec --session-id` inside a pty host, and exit 20 `expired` after an unadopted run (the host must still exit 0); (E) `termctl open --dry-run` against a real open (drift); (F) `--keep-on-exit failed` keeping only failed panes, and the timing of `close_dead`; (G) `never_adopted` is modeled as an `exec` that prints it, while the real sequence is claude-session finalizing the unadopted run later.
