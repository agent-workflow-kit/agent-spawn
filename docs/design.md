# agent-spawn: design

Status: designed (interface 0.1.0-design), 2026-11-02. The normative rules are in [interface.md](interface.md); this document records the decisions, the live verification and the internal architecture, and links to interface.md's headings instead of restating its rules.

## Role and layer

Layer 2 (composite). Launch, resume, park and tear down Claude agents: worktree + terminal + Claude session (architecture section 5.2 and section 9). Works fully standalone (architecture C2): a headless launch with `--worktree none` needs only claude-session; termctl is used only for windows and wtctl only for worktrees and for finding the records of a run's cwd (architecture section 3.2).

## Uses

| Tool | Binding | Used for |
|---|---|---|
| claude-session | A, through one internal session-backend module whose interface is the agent session role (architecture section 3.5) | `start` / `start --resume [--fork]` (each preceded by the same command with `--dry-run --json`), `exec --session-id`, `status`, `list --label`, `stop`, `label add/remove`, `forget`, `verify-secret`, `reconcile` |
| termctl | A | `open` (and `open --dry-run`), `mark`/`unmark`, `focus`, `list --dead`, `close`, `label add/remove`, `placements` |
| wtctl | A | `list`, `show`, `create --holder`, `adopt --holder`, `remove --yes --holder`, `forget --holder`, `baseline check`, `status` |

Executables are configured as argv lists (`claude_session_cmd`, `termctl_cmd`, `wtctl_cmd`), resolved once per invocation to absolute paths; every argv agent-spawn builds for a window or a hook uses absolute paths, so neither depends on its own `PATH` ([interface.md, Config](interface.md#config)). Turning the claude-session edge into binding C (a second vendor's session tool) later is a change inside the session-backend module, not an interface change.

**Dependencies:** `pyyaml` (config), `pydantic` (config validation), `textual` (only `browse`). Everything else is the standard library (`sqlite3`, `socket`, `signal`, `ctypes` for the `pidfd_open` fallback). Test-only (dev group, never shipped): `jsonschema` and `referencing`, which validate every golden `--json` output, hook payload, log and audit record against `schemas/` through a registry keyed by `$id` (`tests/schema_registry.py`).

| D5 | `prune` measures age from the agent's last run, skips agents with attention or protected labels, never forces, and is opt-in. Tombstones are kept 30 days. | Safe public default; workflow-owned agents are their owner's to tear down. | [`prune`](interface.md#prune) |

A lookup error refuses the command before anything changes. wtctl availability: config `wtctl_cmd: null` declares that there is no wtctl on this machine (standalone use: the records of every cwd are empty, a third-party-reading run needs `--cwd session-dir`, worktree flags exit 2); otherwise an unresolvable wtctl exits 12 `tool_missing` whenever the records of a cwd are needed, before anything changes. Review pass 3 (R-7, R-8): the same lookup now also feeds the third-party cwd rule (D49). Safety spot check 1 (SPOT-1): inferring standalone use from "no agent record stores a wtctl path" failed open once tombstones expired or the state dir was fresh, letting a trusted run into a throwaway; standalone use is now explicit. | [Records of a cwd](interface.md#records-of-a-cwd), [Launch order](interface.md#launch-order), [Resume order](interface.md#resume-order) |

| D11 | `--worktree new` maps to `wtctl create --holder`, `<path>` to `wtctl adopt --holder`; `--cwd` stays inside the worktree (compared by realpath); `--ephemeral` tears down only after `done`, and a fork is never ephemeral. After an ephemeral teardown the report artifact's path no longer exists; callers that need it do not use `--ephemeral`. The supervisor runs an ephemeral teardown itself (`live → tearing_down`, still recorded as the teardown process), so waiters return only after it exited and a concurrent `resume` gets 20 `tearing_down`. `--mode` defaults to `interactive` and is always passed explicitly; without a worktree and `--cwd` the cwd is the classification plan's (possibly `session-dir`); `--cwd session-dir` with `--worktree new\|<path>`, and `--worktree <path>` inside a throwaway record, exit 2. | Ephemeral teardown after a failure would lose the evidence. Review pass 3 (CR3-10, STD3-9, ADV3-10, CR3-12): parking before the teardown let a resume race it, and the cwd and mode defaults were unstated. | [Launch flags](interface.md#launch-flags) |
| D12 | Labels: agent-spawn is authoritative and mirrors to the session and live pane (a per-agent pending-mirror queue; re-sync never touches `kind=`, `agent=` or labels it did not add); keys `agent` and `kind` are reserved; `job=` from `job_id_env` at launch and resume, except inside an agent session (`CSESSION_ID` set) and for forks, skipped with a warning at the label cap; `job=` identifies only retries of one job. Self-labeling reads the session secret itself and verifies it with `claude-session verify-secret`, allowlisted keys, add only, refused for tainted or third-party-reading runs, never creates a database. Labels are not authenticated against same-user processes (residual risk). Only the first 30 stored agent labels are mirrored to a pane (termctl allows 32 per pane); a change beyond them is a warning, never queued. | Architecture section 9.1; review pass 1 (SAF1-3, SAF1-8, CR1-21). Review pass 3 (CR3-14): termctl's label cap. | [Labels](interface.md#labels), [Labels on agents](interface.md#labels-on-agents), [Labels on lower tools](interface.md#labels-on-lower-tools), [`label add`](interface.md#label-add--label-remove), [Residual risks](interface.md#residual-risks) |
| D13 | Outcome → agent mapping adds the attention reasons `timeout` and `launch_failed` and splits `killed` by end reason (a human or a cancel ends a run without an attention item; an unexpected signal is `failed`). A deliberately interrupted launch (`not-started` ending `canceled` or `launch_interrupted`, or a launcher interrupted before a session existed) parks `killed` without attention (D44); other `not-started` ends stay `launch_failed`. | Everything that needs the user is visible; intentional stops are not noise. | [Outcome table](interface.md#outcome-table) |
| D14 | Teardown order: live checks (never overridable, re-run after `pre-teardown`; they also refuse while the session's current run is pending or live), `pre-teardown`, wtctl (every held record released with `forget --holder` in stored order, each hold row marked `released`, then the owned record removed with `remove --holder` last), close every dead pane of every run's tmux socket labeled `agent=<agent_id>`, forget the session (skipped without one), tombstone (which also deletes the prompt copies and outcome files); resumable through the named `teardown_step` markers. A promotion can leave more than one dead pane. Review pass 2 (STD2-8, CR2-12, CR2-14): a `partial` removal must never fall back to `parked`. Review pass 3 (STD3-14, ADV3-5, CR3-9, SAF3-9, CR3-S-1): an agent can hold several records; removing the owned record last means an agent never returns to `parked` with its worktree removed; `wtctl remove` already refuses `held`, so no separate check of other agents is needed. | [Teardown order](interface.md#teardown-order), [`teardown`](interface.md#teardown) |
| D15 | `reconcile` runs `claude-session reconcile`, then the liveness check, reports interrupted teardowns (`teardown_incomplete`) and the forks it removed as abandoned (`fork_abandoned`, D46), re-syncs labels, removes orphaned prompt copies and handoff directories of dead owners, and deletes old tombstones; it never runs `wtctl reconcile` and never signals. `cron install` schedules it. | wtctl has its own schedule; coupling them buys nothing. | [`reconcile`](interface.md#reconcile), [Liveness](interface.md#liveness) |
| D16 | `attach` uses `termctl focus --json` and execs the returned argv; `no_window` for live agents whose current run has no window. A minimal Textual `browse` is in the 1.0 scope, as the last stage. | The dashboard drills into it; it is the way to triage several parked agents. | [`attach`](interface.md#attach), [TUI](interface.md#tui) |
| D17 | `supervise` forwards SIGHUP to `exec` (it does not ignore it), ignores SIGQUIT, never writes to its terminal, and sends SIGCONT with a forwarded SIGTERM. | Spike B: a closed window signals only the pane's session leader; without forwarding, `exec` and `claude` live on with no terminal. | D18 | Two terms: a run is **adopted** when claude-session's adoption compare-and-set gave it a wrapper, and **started** when claude-session reports its `phase: session` (D43); a run waiting at Claude's trust dialog is started. Clearing `needs_attention`, `post-launch` and the launcher's return use **started**. `adopt_timeout` is removed: before adoption the wait is bounded by claude-session's pending-run expiry (`never_adopted`), after adoption by claude-session's `pre-launch` hook timeouts and launch validations, after which the run is started or final. `handoff_timeout` bounds only the handoff. | Review pass 1 (STD1-2, CR1-1, SAF1-6): one word was used for both events, and a second timeout raced claude-session's own expiry. | [Concepts](interface.md#concepts), [Launch order](interface.md#launch-order) |
| D19 | The supervisor's PID, start time and boot id are recorded before any adoption is possible (window: the pane PID from `termctl open --json`; detached: the grandchild reports them over a pipe and spawns `exec` only after the launcher recorded them and acknowledged; in-process: the launcher). A supervisor starts by installing its signal handlers, completing the handoff (window), opening the state dir given in argv and checking that the agent record names it as supervisor and is `launching` or `live` (host mode: a promotion is pending); a mismatch exits 2. The window process's handoff deadline comes from argv (`--handoff-timeout` plus 60 s). Liveness never calls `claude-session stop`; a pending run whose supervisor is dead is left to claude-session's expiry and never sets `supervisor_lost`. Once a supervisor is recorded, only its liveness decides a `launching` agent's fate, whether or not the launcher is alive. After the acknowledgement the detached grandchild closes every inherited descriptor except stdio and execs `supervise` (same PID and start time, so the recorded identity stays valid). | No process may cancel a run another process could still adopt. Review pass 2 (CR2-18, CR2-19): the detached PID was recorded after `exec` could already adopt, and the window process had no deadline of its own. Review pass 3 (CR3-1, STD3-7, CR3-17): a live launcher kept a dead supervisor's agent `launching` forever, and a forked child inherited the launcher's state (SQLite connection). | [Supervision](interface.md#supervision), [Liveness](interface.md#liveness), [Launch order](interface.md#launch-order) |
| D20 | Headless agents always run a detached supervisor; `launch`/`resume --wait` waits on it (pidfd; kqueue on macOS) and forwards SIGTERM; `--wait-timeout`, SIGINT, SIGHUP or a SIGKILL of the waiter leave the agent running. Only `--placement here` runs the supervisor in-process, and it implies `--wait`. | User answer R-2: one hosting path for headless runs, and `--wait-timeout` truly leaves the agent running. A waiter SIGKILLed by jobsctl after its grace leaves the agent running to completion (residual risk). | [Supervision](interface.md#supervision), [Signals](interface.md#signals) |
| D21 | Handoff: the launcher listens before `termctl open` and accepts only after it returned, answering only the connection whose peer PID equals the pane PID and whose start time matches; others are closed and logged. `pid: null` or `state: gone` fail at once. The window process sends nothing; the launcher sends one JSON object, ended by `shutdown(SHUT_WR)`, at most 4 MiB. The peer check is the authentication (no nonce); the window argv carries only the agent id, socket path, state dir, config path and handoff timeout. | Review pass 1 (SAF1-7, STD1-12, CR1-18): a connection could arrive before the PID was known; the start time closes PID reuse. agent-spawn's absolute path must exec in place. Review pass 2 (CR2-S-4): a request from the window added nothing. | [Environment handoff](interface.md#environment-handoff), [Platform notes](interface.md#platform-notes) |
| D22 | Every lifecycle entry is a compare-and-set under the agent's lease, made before the command's own lower-tool calls and hooks: `resume` `parked → launching` (recording `expect_run_after`, the session's current run number), `teardown` `parked → tearing_down` (back to `parked` on a veto), the supervisor `launching → live` when the run is started and `live → tearing_down` for an ephemeral teardown (D11). The liveness check that precedes an entry, which may call lower tools, runs without the lease; the compare-and-set then re-reads the row under the lease. No lower-tool call or hook runs while the lease is held. The loser exits 20. | Review pass 1 (STD1-9, CR1-2, SAF1-9): claude-session's `live` refusal alone left races before `start` (worktree, checks, hooks). Review pass 2 (CR2-8): liveness can restore an interrupted resume that started no run. Review pass 3 (CR3-15): the order of the liveness check and the lease was unstated. | [Lifecycle transitions](interface.md#lifecycle-transitions), [Resume order](interface.md#resume-order), [Teardown order](interface.md#teardown-order) |
| D23 | Retries are deterministic: without `--worktree-name` the worktree name is the agent id. A resume with no stored `wt_record_id` looks for a live record of the planned name that this agent holds (`wtctl list --repo`): `active` is reused, `creating` parks `launch_failed` with a `wtctl reconcile` hint, none creates. `wt_record_id` is stored from every create result. A resume with a record skips `create` when the record is active; a live record in another state (`unlinked`, `missing`, `clone_missing`, `partial`) parks `launch_failed` (`details.cause: worktree_state`) for a human to repair or forget. | A resume after a crash must not create a second worktree. Review pass 3 (CR3-18): the other record states had no rule. | [Resume order](interface.md#resume-order), [Names](interface.md#names) |
| D24 | Name rule: `--name`, else `--worktree-name`, else `<kind> <first 6 id characters>` (kind `agent` when none was given); known at allocation, never null. | Review pass 1 (CR1-8, KG-2): the old default depended on a worktree that may not exist yet. | [Names](interface.md#names) |
| D25 | A fork's record is inserted at allocation (D46, revising review pass 1's "only after `start` succeeded"). A fork of a live source is allowed. ## Live verification

Spikes ran on 2026-11-02 (Linux 5.15, tmux 3.5a and 3.2a, Python 3.10/3.12/3.13, Claude Code 2.1.316 with `--model haiku`), each in a scratch directory with a private tmux socket. Every relied-on behavior below becomes a `live` or process test in the plan.

| Spike | Question | Result | Consequence |
|---|---|---|---|
| A1–A4 | Hand an environment to a process in a new tmux window over a FIFO | Works in about 30–40 ms; 1 MiB payloads arrive intact; the FIFO node stays empty on disk | Handoff is viable (D4) |
| A5 | What a window's process inherits | The server's environment plus `TERM`, `TERM_PROGRAM(_VERSION)`, `TMUX`, `TMUX_PANE`; a new window's `PATH` comes from the tmux client that created it | Terminal variables are taken from the pane |
| A6–A7 | Theft and authentication | A same-uid process opening the FIFO first steals the payload; a Unix socket with `SO_PEERCRED` and a peer-PID check against `#{pane_pid}` rejects it | Socket with peer check (D4) |
| A8 | `pane_pid` binding | `#{pane_pid}` equals the window process's PID (`/usr/bin/env` execs) | The peer check is reliable |
| B1–B3 | Signals on window close (`kill-pane`, `kill-window`, `kill-session`, `kill-server`) | Only the pane's session leader gets SIGHUP and SIGCONT; its children get nothing until it exits | `supervise` forwards SIGHUP (D17); architecture section 9.2 corrected |
| B2 | Writing after a hangup | EIO, which kills an unprepared process before bookkeeping | `supervise` never writes to its terminal |
| B4 | Ctrl-C, Ctrl-\, Ctrl-Z in a window | SIGINT and SIGQUIT reach the whole foreground group; SIGTSTP is discarded (orphaned group) | `supervise` ignores SIGQUIT; claude-session's `exec` should too (carry-forward) |
| B5 | SIGTERM chain from outside tmux | pidfd plus start-time check plus forwarding through `supervise`, `exec`, child: about 3 ms | Cancellation chain (interface, Signals) |
| B6 | `remain-on-exit` | `failed` keeps a dead pane only on a non-zero exit | Windows use `--keep-on-exit failed`; `supervise` exits 0 |
| B9 | `supervise` SIGKILLed | The kernel hangs up `exec` and `claude` when the pane closes; a child ignoring SIGHUP survives orphaned | `supervisor_lost` and `claude-session stop` (interface, Liveness) |
| C1–C2 | Double fork + `setsid` | Detached process has no terminal, survives window close and parent hangup | Detached hosting |
| C3 | Under a subreaper job shim | Detached process is reparented to the shim; group signals do not reach it; without a stdio redirect it holds the shim's pipe open for its lifetime | The detached supervisor redirects stdio; jobs use `--wait` |

| C5 | Logout | Detached processes stay in the login session's cgroup; they survive here (`KillUserProcesses=false`), would not with `yes` | `awkit doctor` check (Residual risks) |

| D4 | Minimal environment | `claude` authenticated with only `PATH` set | The handoff's full environment is more than enough |

## Internal architecture

### Modules (`src/agent_spawn/`)

| Module | Responsibility |
|---|---|
| `cli` | argparse, global flags, human-only gate |
| `config` | YAML loading, drop-ins, Pydantic validation, `AGENT_SPAWN_*` overrides |
| `store` | SQLite schema, migrations, leases (`agent`, `delivery`, `reconcile`), agent/label/run/hold/event tables |
| `ids`, `labels` | id allocation and prefix resolution; label grammar and multiset operations |
| `gateway` | every subprocess call (claude-session, termctl, wtctl, `crontab`) |
| `session_backend` | the agent session role over claude-session, including the dry-run classification and the post-start check (D39) |
| `term` | termctl calls (open and its preflight, mark, focus, close, labels) |
| `worktrees` | wtctl calls, the records of a cwd, the holder rule and the third-party cwd checks (D6, D49) |
| `procs` | spawn, double fork with the PID pipe and acknowledgement, process identity (PID, start time, boot id, zombie), pidfd with `ctypes` fallback (kqueue on macOS), signal forwarding |
| `handoff` | the peer-checked socket (listener in the launcher, client in `supervise` and its host mode), framing, deadlines and the `owner` file |
| `launch`, `resume` | the launch and resume orders, prompt copies, lifecycle compare-and-set entries, the fork record at allocation (D46) |
| `supervise` | startup check, polling for started (D43), the run loop, outcome table, window markers, outbox draining, automatic report resume, promotion, the chain-failure park (D48) and host mode (D47) |
| `relay` | `_session-event`: records events and state only (D42) |
| `teardown`, `prune`, `reconcile`, `liveness`, `stop` | as named |
| `hooks` | design-guide hook execution, selectors, payloads, the outbox and its delivery lease |
| `output` | result objects, error envelopes (`lower_error`), `--result-file` writes (no-follow, atomic) |
| `browse` | Textual TUI (last stage) |

### Data model (`state.db`)

- `agents`: id, `csession_id` (set only from `start`'s output, D35), `forked_from`, launch kind, last run kind, mode and placement (both the last run's), `term_placement`, name (never null), repo (`--repo`, else the dry-run plan's, confirmed from `status`), cwd (realpath, or `session-dir`), worktree (`wt_record_id`, path, owned), the host pane PID during a promotion, `tainted` (the session's taint from `status` after each `start`; null without a session), `expect_run_after` (the session's run number when `resume` entered `launching`, null without a session), the absolute paths of agent-spawn, its state dir, its config file, claude-session, termctl and wtctl resolved at launch (used by every internal argv), the launch actor and decision ids, supervisor/`exec`/launcher PIDs with start times and boot id, the run-chain starter (the `launch`/`resume --wait` process that acts on SIGTERM), `promote` (explicit `true`/`false`/null), `ephemeral`, status, `needs_attention`, `park_reason`, `escalated_by` (`wtctl`, `termctl`, `claude-session`; non-null only when a hook escalation parked the agent), `promotion_pending` (false after every park), the last outcome object, `supervisor_lost`, `teardown_step` (`started`, `hooks_done`, `worktree_partial`, `worktree_done`, `windows_done`, `session_done`; null when not tearing down), `teardown_partial_record` (the record that went `partial`, D14), `created`, `last_live_at`, `updated`, `torn_down_at`, and the stored launch settings, `--skill` and pass-throughs needed to complete a launch on resume (also the `pre-launch` payload's `settings` and `pass_throughs`). There is no `last_exit_code` column (the outcome object carries it), no adoption deadline (`adopt_timeout` is removed), no stop request (D45) and no window column: the agent object's `window` is the current (or last) run's.
- `agent_runs`: run number, kind and the dry-run plan's `run_kind`, mode, placement, cwd, classification (`reads_third_party` from the dry run, D39), window (`term_id`, `socket_path`, pane PID; null when the run had none), outcome, end reason, exit code, report status, `auto_resumed`, `promoted`, `first_working_at` (the first relayed `working` activity, else filled from `status` `recent_events` when the run is finalized, else null), the outcome file token, the per-invocation `--hook` entries, the last relayed session state, activity and `needs_input_reason`, times.
- `agent_holds`: the worktree records an agent holds now (the agent object's `holds`): agent, `record_id`, path, `owned`, stored order and `released` (set by teardown, D14). A re-adoption that creates a new record replaces the id on its row (and in the agent's `wt_record_id` when it was the launch record). Throwaways never have a row. There is no flag table (D49).
- `agent_labels` (multiset, stored order kept for the termctl subset), `label_mirror_pending` (per agent: label pairs added or removed that the session or pane has not received yet), `relay_events` (relayed `(csession_id, event_id)` keys, pruned after 7 days), `events` (agent-spawn's own hook outbox: `event_id`, agent, event, payload, delivered flag), `leases` (holder PID, start time, expiry; keys `agent:<id>`, `delivery:<id>` and `reconcile`), `meta` (schema version).
- Files outside the database: `<state>/prompts/<agent_id>/` (0700, prompt and input copies from classification until a session is allocated), `<state>/outcomes/<agent_id>/` (deleted at teardown's tombstone step; `reconcile` removes leftovers of torn-down agents), the handoff socket directories with their `owner` file ([Files](interface.md#files)).

### Concurrency

Every lifecycle entry is a compare-and-set on `status` under the agent's lease, made before the command's own lower-tool calls and hooks: `resume` moves `parked → launching` (recording the launcher and `expect_run_after`) before the pre-start checks; `teardown` moves `parked → tearing_down` (`teardown_step: started`) before `pre-teardown` and back to `parked` on a veto or escalation; the supervisor moves `launching → live` when the run is started (D43) and `live → tearing_down` for an ephemeral teardown (D11); a park after a failed placement is written only by the process that wins `launching → parked`. A loser exits 20 (`live` or `tearing_down`). The liveness check that precedes an entry, which may call lower tools, runs without the lease; the compare-and-set then re-reads the row under the lease. The agent lease is held only around these transitions and other state writes, never while a lower tool, a hook or a session runs; teardown therefore re-runs its live checks after the `pre-teardown` hooks. claude-session's atomic `live` refusal remains a second line.

There are no location leases (D41 withdrawn): the third-party cwd rule (D49) reads only wtctl's records and needs no shared state. **Delivery lease** (`delivery:<agent_id>`) serializes the outbox (D34): its holder delivers every undelivered event of the agent in `event_id` order, and a process that cannot take it leaves them to the holder. The relay writes in one transaction and is idempotent on `(csession_id, event_id)`; `reconcile` holds its own lease. A dead holder's lease is taken over at once (PID plus start time). See [Lifecycle transitions](interface.md#lifecycle-transitions).

### Outcome files

Every `start` passes `--outcome-file` into `<state>/outcomes/<agent_id>/`; the session id is not known before `start` returns, so the file name uses a random token, recorded with the run. The supervisor reads the outcome from that file (claude-session writes it exactly once, whoever finalizes the run), checks that its `csession_id` and `run` equal the run it adopted, and falls back to `status --json` on a mismatch, a parse error or a missing file. For a promoted run it reads the file after the host pane PID exited (D47).

### Error handling

A lower tool's failure is passed through with its exit code and `tool` set, and its whole error object in `lower_error` ([Error envelope](interface.md#error-envelope)); agent-spawn adds `agent_id` when a record exists and maps the lower code per D38. Failures after the agent record exists park the agent (D3); failures before a run of a resume exists restore the pre-resume row ([Resume failures](interface.md#resume-failures)); a fork that fails before its session exists removes its record, and liveness removes an abandoned fork (D46); a supervisor-initiated run that is refused or fails parks per the triggering run (D48). The relay always exits 0 and logs (with an older database schema it processes the event when readable, else logs `schema_older`; without a database it logs and exits 0).

## Test strategy

- Unit tests per module with the gateway faked.
- Fake binaries in `tests/fakebin/` for `claude-session`, `termctl`, `wtctl` and `tmux`, returning canned JSON validated against the siblings' schemas copied into `tests/` and pinned to their interface versions; they log invocations.
- Golden-file tests of every `--json` output, validated against `schemas/`.
- Process tests (local, no model): double fork, the PID pipe and acknowledgement, and stdio redirect, pidfd waits and the `ctypes` fallback, zombie handling, SIGTERM/SIGHUP forwarding chains, the handoff peer check against a private tmux server (`-S` in a temporary directory) including a thief connection, window close with a stand-in `exec`, supervisor startup with a record that does not name it (exit 2), the detached grandchild execing `supervise` with the same PID and start time and no inherited descriptor or SQLite connection (D19).
- Classification (D39): a launch with `--kind implement --reads-third-party`, then `resume --kind implement`, is third-party-reading; a plain resume and a fork of a `respond` source without `--kind` are third-party-reading; a dry-run failure starts nothing; `would_refuse` refuses before anything changes; the post-start check: a run classified trusted that is third-party-reading continues with a `warn` log in its session dir and is canceled and parked `launch_failed` (`classification_mismatch`) in a worktree; a run classified third-party-reading that is trusted continues with a `warn` log in its session dir and is canceled in a throwaway; a `status` failure after `start` cancels the run and parks `classification_unknown`.
